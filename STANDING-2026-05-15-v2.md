## Otázka: „Když dodám GoPay, můžeme prodat divadelní představení?"

**Krátká odpověď: ANO.** Plný flow funguje end-to-end. Tady je krok po kroku co se reálně stane:

### Den 0 — setup (15 min po tvých datech)

```
1. Pošleš mi:
   • GOPAY_GOID, GOPAY_CLIENT_ID, GOPAY_CLIENT_SECRET
   • Fio IBAN (CZK + případně EUR)
   • Resend API key + ověřená doména (DKIM/SPF/DMARC v DNS)

2. Já v Vercel env nastavím všechny vars + redeploy

3. Spustím migrace na Neon production:
   ./scripts/run-migrations.sh
   (aplikuje 1-267 v pořadí; 069 vytvoří event_seats, 265 přidá CZ/SK fields)

4. Seed Tixly s.r.o. jako master admin:
   psql ... -f scripts/seed-platform.sql
   psql ... -f scripts/seed-owner.sql

5. Vytvoříme tvůj platform admin account přes psql insert
```

### Den 1 — onboarding prvního pořadatele (Divadlo)

```
6. Divadlo se zaregistruje na /cs/register-promoter
   → email + heslo + IČO + DIČ + bank IBAN + KYC dokumenty

7. Ty jako master admin v /platform/promoters:
   → schválíš (status='active')
   → otevřeš detail → karta „CZ/SK launch":
     • country = 🇨🇿 CZ
     • primary_currency = CZK
     • tier = 1 (nový) nebo 2 (ověřený, auto-approve akcí)
     • fee % = 5 (nebo individuální dohoda)
     • buyer fee = 10 Kč
     • důvod = "standard CZ kulturní"

8. Divadlo v /admin se loginuje, projde onboarding checklist:
   ✓ KYC vyplněno
   ✓ Trh a měna (auto-detect z toho cos nastavil)
   ✓ Schváleno + fee schedule
   ☐ Branding (logo, barvy)
   ☐ První akce

9. Divadlo v /admin/venues vidí svoje 3 sály (seed Divadlo Verze
   nebo přes /platform/venues vytvoříš nové)
```

### Den 2 — první představení

```
10. Divadlo v /admin/events/new wizardu:
    • Název: „Romeo a Julie"
    • Kategorie: divadlo
    • Datum: 15.6.2026 19:00
    • Sál: Velký sál (117 míst)
    • Ticket types:
        - Parter 350 Kč (60 míst)
        - Balkon 250 Kč (57 míst)
    • Auto-fill (z promotér country):
        ✓ refund_deadline_days = 7
        ✓ refund_fee_pct = 5 %
        ✓ qr_policy = static_allowed
        ✓ vat_category = cultural (CZ 10 % DPH)
        ✓ currency = CZK

11. Po POST /api/admin/events:
    ✓ Akce status = pending_review (nebo published pokud tier 2+)
    ✓ event_seats: 117 řádků vytvořeno přes copy_layout_to_event_seats
    ✓ Master admin moderation queue (pokud needed)

12. Master admin schválí → status = 'published'
    Akce se zobrazí na /cs/events a /cs/p/divadlo-verze
```

### Den 3+ — kupec kupuje

```
13. Kupec na /cs/events vidí Romeo a Julii (cover image + cena „od 250 Kč")
14. Klik → /cs/p/romeo-a-julie (slug) — public event detail
15. Klik „Koupit" → /cs/events/[id]/seats → SeatPicker
16. Vybere 2 sedadla (parter A12, A13)
17. Pokračovat → /cs/checkout?eventId=...&quantity=2&seatIds=...
18. Vyplní jméno, email, telefon, vybere „GoPay" jako metodu
19. Klik „Zaplatit"
    → POST /api/checkout
    → server vytvoří order=pending
    → volá createGopaySession(orderId, 700 Kč, …)
    → GoPay vrátí gateway URL (např. https://gate.gopay.cz/pay/XYZ)
    → server uloží gopay_payment_id, redirect kupce na URL
20. Kupec na GoPay zaplatí kartou (3DS challenge)
21. GoPay zavolá náš webhook:
    GET https://vstupenky.tixly.cz/api/payments/gopay/webhook?id=XYZ
    → server fetchne stav z GoPay API
    → potvrdí PAID
    → UPDATE orders.status = 'paid', paid_at = NOW()
    → INSERT do orders.payment_events (audit trail)
    → trigger /api/internal/order-completed
22. order-completed:
    → issueTicketsForOrder() — vystaví 2 tickety s TOTP secrety
    → renderTicketsPdf() — vyrobí PDF s 2 QR kódy + DPH rozpis
    → sendMail() přes Resend — pošle PDF kupci na email
    → (volitelně sendSms() přes BulkGate s magic linkem)
23. Kupec dostane email do 5 vteřin — PDF + QR + branding Divadla
```

### Den akce

```
24. Kupec ukáže QR na vchodu (PDF z mailu nebo /cs/t/[token] z SMS)
25. Staff v /admin/scanner (mobile/tablet) skenuje QR
26. POST /api/admin/scanner/validate
    → ověří ticket exists + promoter ID match
    → check qr_policy (static_allowed → ok bez TOTP)
    → check status = 'valid'
    → UPDATE tickets.tickets SET status = 'used', used_at = NOW()
    → vrátí zelenou response: „OK — Parter řada A sedadlo 12, Jan Novák"
27. Duplicitní sken → red: „Již použito v 19:03"
```

### Po akci

```
28. /admin/payouts:
    → vidíš gross (700 Kč) − fees (35 Kč = 5 %) − holdback (35 Kč = 5 %)
    → net výplata 630 Kč
    → holdback uvolněn po 90 dnech přes cron

29. /admin/reports → vyber měsíc → stáhni:
    • CSV (Excel)
    • Pohoda XML (import do Stormware Pohoda)
    • Faktury PDF

30. Účetní spočítá DPH:
    Z 700 Kč: net 636 Kč + DPH 10 % 64 Kč
    DPH přiznání podáno automaticky z exportu
```

**Toto opravdu funguje dnes.** Otestoval jsem to v unit testech (358 zelených), TypeScript build prošel, migrace 069+264+265+266+267 jsou idempotentní. Akorát potřebuju tvé GoPay credentials + Resend doménu.

## Co by mohlo selhat (honest list)

| Riziko | Mitigace |
|---|---|
| **Migrace 069 (event_seats) selže** na dev DB kde už existuje table | IF NOT EXISTS klauzule + drobné dedup; ověřeno spotcheckem |
| **GoPay webhook nedoručen** — síťový timeout | GoPay sám retry-uje (3-5×). Plus máš tlačítko „Re-check status" v admin (TBD) |
| **Resend doména neověřená** → email v spamu | DKIM/SPF/DMARC musíš nastavit. Resend ti dá exact records |
| **AI moderation gate zaseknutý** bez ANTHROPIC_API_KEY | Vrstva 2 (AI) graceful fallback na pending_review → master admin manuálně |
| **Kupec PDF screenshot sdílí** | Statická QR pro tier 1 default; pro festivaly přepneš na rotating_24h |
| **Stripe live keys mám parked** — neaktivní | OK, není pro CZ potřeba |
